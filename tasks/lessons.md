# Lessons

- **Eval reports are named by date and prompt version, so a rerun on the same prompt and day overwrites the earlier report.** On 2026-10-20 a 3-case rerun overwrote the full 327/335 baseline report (`api/evals/results/` isn't tracked by git, so it couldn't be recovered; its findings survive in `todo.md`). Rule: before any run on a prompt version that already has a report today, move the existing report aside, or fix the runner so it never overwrites.
- **Don't write C# or regex literals through Python heredocs or `sed`.** Escapes get eaten: `\\n` became a real newline, `\b` a backspace character, and `sed -i` stripped backslashes and turned CRLF files into LF. Rule: use the Edit tool for these files, then run `dotnet format --verify-no-changes`. That includes temporary edits: on 2026-10-21 a `sed` that put back an old `<footer>` to show a test failing also rewrote an unrelated `</div>` with the same indentation. Show-it-failing edits use Edit too, one pair to break and one to restore.
- **`awk -v` interprets backslashes, so a Windows path passed that way is silently mangled.** On 2026-10-21 a `getline` from the mangled path read nothing, and the replacement deleted Phase 2's tasks from `todo.md`; the backup restored them. Rule: pass paths to awk through `ENVIRON`, and keep a backup before any scripted rewrite of a doc.
- **Testing Library only unmounts between tests when Vitest's globals are on, and this repo doesn't enable them.** On 2026-10-21 a hook test failed because the previous test's hook was still mounted and handled the event first. Rule: every jsdom test file calls `cleanup()` in `afterEach`.
- **A component test doesn't see invalid HTML, and a page without a background inherits the browser's dark scheme.** Both showed up only in the browser check (a spinner `<div>` inside a `<p>`, and a dark-on-dark privacy page). Rule: read the console and look at both widths before calling a UI step done; pin each finding with a test where one can catch it.
- **A failing grader check isn't always a model failure.** Several rounds found correct answers failed by case patterns ("doesn't say Jack was fired" tripping a pattern meant to catch "Jack was fired"). Rule: read the actual answers before changing the prompt, and pin every false positive as a test row in `EvalSetTests` before fixing it.
- **Prompt rules can backfire.** Round 11's "and suggest emailing Jack" made `trap-java` worse, and round 5's refusal rule caused over-refusals. Rule: rerun the cases a rule targets, plus a full run, before keeping it, and revert rules that don't help.
